# Rubric: is this a good first issue?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Maintainer activity | Eval: dates and authors of the last five default-branch commits and maintainer first-response sample in Repo facts. Live: default-branch commit history and recent issue replies by an Owner, Member, or Collaborator. Compare dates with the bundle capture date in eval mode and today in live mode. | At least one human-authored default-branch commit or merge of a human PR within 180 days, or one maintainer reply in the sample within 90 days. Bot-only activity does not qualify. | required |
| Repository in use | Eval: archived flag, last push, latest release, and default-branch dates in Repo facts. Live: archive banner, branch history, and Releases page. | The repo is not archived and has a push, release, or default-branch commit within 365 days. A release is not mandatory when code is actively maintained; stars do not substitute for activity. | required |
| Bounded contribution | Eval: issue body and every shown comment, including linked-attempt history. Live: issue body and full thread, including maintainer clarification. | Pass a single observable bug, a coherent docs workflow, or one feature family whose result can be checked, even when it spans several files, includes optional tactics, or is tersely described by a maintainer as a good first issue. Fail an explicit umbrella/tracker, a support question, or an unsettled design discussion with no current maintainer decision. Also fail when years of debate and multiple abandoned PRs leave the present approach unresolved, or when a new feature depends on an unspecified product choice or asset (such as which branding/logo to ship). A short bug report, missing repro steps, or multiple suggested causes alone do not fail. | required |
| Available to take | Eval: assignees and linked-PR states in Repo facts, plus issue comments. Live: Assignees and Development panels and thread. | No current assignee, open linked or thread-mentioned implementation PR, or active claim by someone else. A closed unmerged PR is not active. A claim over 90 days old with no follow-up is stale, especially when a maintainer invites new takers. In live Path Review mode, classmates' claim comments do not block the issue, as scope.md directs. | required |
| AI contribution policy | Eval: contribution-policy line in Repo facts. Live: CONTRIBUTING.md, linked contributor policies, dedicated AI policy files, and issue or PR templates. | No stated ban on AI-assisted code or documentation. Silence passes. Disclosure, review, testing, and personal-understanding requirements pass as conditions to follow, not bans. An explicit refusal of AI-generated contributions fails for this AI-assisted course workflow. | required |
| Personal fit | Eval: issue body and Repo facts. Live: issue body, relevant files/tests, and the fit profile in scope.md. | Preferred when a Python change is isolated, has a direct reproduction or focused test, and can plausibly be investigated in a few hours. This only ranks accepted live candidates. | preferred |

## Verdict rule

Accept only when every required check passes. Reject when any required check fails or is unclear after consulting its named evidence. Preferred checks never change accept/reject; use them, together with the fit profile, to rank accepted candidates. Grade the snapshot as of its capture date in eval mode and current GitHub evidence in live mode.
