# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | Plan context or plan.md scope, exclusions and deviations paired with every changed file/hunk, commits, and candidate title/description | The diff implements the bounded plan in both directions and its claims match the delivered behavior. Any added, deferred, or altered work is explicitly justified in the plan's deviation notes and represented honestly in the description. A disclosed, bounded shortfall can pass; silent extra work, silent omissions, or a false exact-plan/full-coverage claim fails. | required |
| Reproduction and controls | Test evidence paired with the issue's trigger, accepted repro, plan's expected-after and control/test plan, and regression assertions in the diff | Evidence observes the reported trigger before and after and makes the expected changed behavior checkable, with relevant controls or a bounded explanation of any deferred control. The test exercises the actual failure shape; a nearby happy path, assertion comment, generic success claim, or 'works for me' is insufficient. A stated limitation can pass when the core claimed result remains demonstrated and the description does not overclaim. | required |
| Repository checks | Test-evidence command/outcome records paired with the repo-facts stated checks or live contributing instructions, and description's testing claims | The relevant repository-prescribed checks were actually run and their outcomes are recorded. A named command plus an explicit outcome/count is evidence; do not demand raw terminal logs when the frozen bundle supplies a concrete run result. Bare 'all tests pass', added test code without execution, or only personal use does not prove a run. Disclosed failures, skips, empty suites, or unavailable environments may pass when attempts, reasons, and impact are visible and the core fix is still demonstrated; mandatory repository gates remain binding. Distinguish CI not yet possible before PR creation from falsely claiming green CI. | required |
| Diff quality | Complete unified diff and commit list, read against the issue and plan boundary | The substantive fix and tests are directly reviewable, with no unrelated refactor, formatting churn, debug residue, commented-out experiment, or other debris obscuring them. Supporting changes such as a required changelog are related. Judge the contents, not line count, number of commits, or whether a helper has a clever name. | required |
| Standards and communication | Repo-facts template/policy and explicit thread direction paired with the candidate description and relevant diff artifacts; live PR template and docs/CONTRIBUTING.md | Every applicable stated template ask is substantively answered, required issue linkage and supporting artifacts are present, explicit maintainer direction is engaged, and required AI disclosure/policy conditions are honored. Empty headings and boilerplate do not answer an ask. Accept equivalent concise wording and explained N/A items; do not invent a policy where none is stated. Factual fidelity claims belong to Plan fidelity. Do not imply a human review or a CI result that the evidence does not establish. | required |
| Review navigation | Candidate title and description paired with the bounded issue, changed behavior and evidence | A reviewer can identify the trigger, result and evidence without reconstructing the purpose from unrelated material. Terseness alone is not a problem. | preferred |

## Verdict rule

Return accept only when every required check passes. A fail or unclear on any required check returns reject. Preferred checks never change the verdict; their fail or unclear grades remain visible. Use fail for an observable contradiction or missing mandatory artifact, unclear when necessary evidence cannot be verified. Honest outcomes matter: a disclosed and justified deviation or limited result is not automatically a failure; apply the exact check condition rather than requiring perfection. An explanation cannot waive an explicit repository prohibition or mandatory gate. Before a live PR exists, future CI is a disclosed pending step; after it exists, a stated green-CI review/submission gate requires observed green checks.
