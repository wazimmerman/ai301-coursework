# Evidence guide: where evidence lives in a PR package

## Plan fidelity (harness category: silent-drift)

In eval mode read Plan context for accepted reproduction, scope pair, named files, promised tests/docs, exclusions and deviation notes; compare Candidate PR / Diff and Commits, then Title and Description. In live mode read the named plan.md including Deviations, the real issue thread (including the student's posted plan), git diff main...HEAD and git log main..HEAD --oneline, then the first line and body of pr_draft.md. Verify all files and outcomes in both directions. A smaller result with a justified plan deferral and accurate PR wording can be ready; an unexplained extra refactor, missing promised documentation, or 'implements exactly' contradicted by the diff is silent drift.

## Test evidence (harness category: not-tested)

In eval mode read Plan context's repro and test plan against Candidate PR / Test evidence, test hunks in Diff, and Repo facts' required checks. In live mode pair plan.md and William's real reproduction thread with test_evidence.md's captured commands, environment, baseline/head, stdout/stderr and exits; inspect the regression assertions in the committed diff and commands in docs/CONTRIBUTING.md/Makefile. Good evidence uses the same trigger, shows the failure before and expected changed behavior after, and records relevant controls and repository-check outcomes. A concrete named suite/result summary in a frozen bundle counts even without raw logs. A wrong-trigger happy path, a comment pretending to assert, unexplained 'all tests pass', or tests merely added does not. Preserve attempted-run failures and no-tests-collected outcomes honestly. Do not count generated mock output as observed evidence or require live reruns of frozen bundles.

## Diff quality (harness category: unreviewable)

In eval mode use Candidate PR / Diff and Commits, paired with Plan context; in live mode use the complete three-dot committed diff and commit list, with git status --short exposing uncommitted work outside that package. Good changes keep the fix, regression tests and required supporting artifacts visible. Find debug prints, dead experiments, commented code, incidental formatting and drive-by refactors by reading the hunks themselves. A small diff can still hide a harmful change; multiple focused commits can be reviewable. Do not demand squashing or extra cleanup unless the repo states it.

## Standards and comms (harness category: standards-wall)

In eval mode Repo facts supplies the captured PR-template asks, contributing policy and AI rules; Issue/Thread highlights supplies explicit direction; Candidate PR / Description and Diff show compliance. The snapshot wins over today's external repository; no live fetch is permitted. In live mode read .github/PULL_REQUEST_TEMPLATE.md and docs/CONTRIBUTING.md on the target baseline plus the full issue thread, then pr_draft.md and committed required artifacts. Check meaningful answers to every applicable ask, issue number, actual test outcomes, required docs/changelog, and truthful AI disclosure. Explained N/A and substantively equivalent concise wording can satisfy an ask; blank boilerplate cannot. Do not invent an AI ban or a human-review statement. Before opening, leave CI unchecked and state that it has not yet run; after opening inspect actual checks when policy requires them. Personal voice lives only in voice-guide.md and is reported separately in live mode. Universal review navigation uses the candidate title and description to locate the trigger, result and evidence; factual coverage claims are assessed under Plan fidelity.
