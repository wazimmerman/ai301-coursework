# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Specific claim | Candidate claim comment read against the issue's symptom, requested behavior, and thread; see the Comms section of the evidence guide. | The claim names this issue's concrete behavior or component and one next investigation or reproduction action. It does not merely ask for assignment, echo another commenter, guarantee a fix, or promise a deadline. A claim written before reproduction promises a report without asserting it exists; a claim written after a completed attempt may accurately summarize that result and point to its report. | required |
| Comparable environment | Repro report's environment record compared with the issue's target version, OS, configuration, and the repo-facts block; see Environment in the evidence guide. | The report identifies the OS/platform, tested app or code version or commit, and any dependency, driver, build mode, or configuration that can change this issue's behavior. A material difference from the issue's target is stated rather than silently treated as equivalent. | required |
| Followable trigger | Repro report's starting state, commands, inputs, and setup read against the issue's stated trigger; see Steps in the evidence guide. | A stranger can recreate the tested starting state and perform the action that is supposed to trigger this issue using public or included inputs. Missing private configuration or skipped issue-critical steps fail, regardless of how polished the prose is. | required |
| Behavior artifact | Repro report's actual output, log, screenshot description, measurement, or other captured observation read against the issue; see Behavior shown in the evidence guide. | At least one concrete artifact shows the reported symptom or shows what happened in a faithful failed attempt. A version banner, successful startup, assertion of reproduction, or speculative cause alone does not show behavior. A control run helps but is not mandatory when the main artifact is decisive. | required |
| Faithful target | Issue's exact trigger and expected symptom compared with the report's input, environment, output, and conclusion; see Behavior shown and Honesty in the evidence guide. | A reproduction claim passes only if the artifact demonstrates the issue's behavior rather than an adjacent error, altered input, or unrelated version. A cannot-reproduce report passes when it shows a faithful attempt, clearly says the symptom did not occur, and calls out meaningful environment or input differences. | required |
| Supported conclusion | Repro report's expected/observed statement, certainty, and cause claims compared with its artifacts; see Honesty in the evidence guide. | The conclusion says no more than the evidence shows. It separates observed behavior from possible causes, does not claim a fix or broad reproducibility without proof, and may honestly conclude cannot reproduce when the attempt and its limits are evidenced. | required |
| Repository conventions | Repo-facts contribution policy and issue template compared with both candidate comments; in live mode check linked contributor policy files and the voice guide; see Comms in the evidence guide. | The comments comply with stated issue/comment conventions and any AI-use rule. Treat every course eval package as AI-assisted work even when the comments do not mention AI. If the repo requires disclosure of any AI use, at least the applicable comments must state the tool and extent of assistance; silence is a failure, not evidence that no AI was used. A policy with no issue-comment disclosure rule adds none. | required |

## Verdict rule

For a full package, accept only when every required check passes; fail or unclear on any required check means reject. In claim-only live mode, grade Specific claim and Repository conventions now, report each check that needs the repro report as `unclear` with `not yet applicable: claim-only draft`, omit those checks from the verdict rule, and accept only if the two applicable checks pass. Preferred checks, if added, never affect the verdict. Judge the evidence and outcome, not headings, length, or formatting.
